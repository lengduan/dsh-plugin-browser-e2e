01系统上下文：谁在跟谁说话

插件分两个半区：宿主半区跑在 DSH 宿主进程里（工具 + 浏览器 + 面板服务端），客户端半区是右侧栏里的 React bundle（纯视图）。两侧唯一的在线通道是面板协议 v1 的 WebSocket。

02分层与依赖：按「接口契约」分层，按「变化原因」切文件

纵向是接口契约分层（接口层 / 编排层 / 实现层 / 公共层），横向按变化原因拆文件。依赖方向按 import 实测标注；禁的是「回指」——页面层不 import 会话层，投屏层不 import 会话层。

03跨调用不变量：14 个纯函数守着状态组合

判别口径只有一条：违反条件来自跨多次调用积累的状态（会话状态机、标签页注册表、ref 表、投屏会话、 连接生命周期），换一次调用不会自愈，必须修状态或重启，才收敛进 lib/invariants.js。 只由本次入参决定、改参数重试即可的校验，留在各能力函数入口，不进这里。

分组断言判据违反后果（状态已经被破坏时的表现）

生命周期		 assertNotClosedDuringLaunch(session) 状态不是 closing / closed 启动与关闭并发：在已摘除的会话上继续 newPage，留下半初始化会话与孤儿进程

04会话状态机：5 个显式状态替代 4 个布尔字段

会话原来靠 launching / launchingPromise / launchTask / closed 四个字段交叉推断状态；现在转移只走 nextSessionState(state, event) 这一张表，转移函数是纯函数（不读全局 Map）， 非法转移直接抛错，全部合法 / 非法组合由 tests/invariants.mjs 覆盖。

状态机之外的会话口径

口径规则
ready 允许 0 页标签页增删不改会话状态；0 页是可恢复态。page.on('close') / ('crash') 只调 removePage，浏览器是否关闭只由 close 决定
复用分支已有浏览器时同样建立落定信号；返回前复查会话仍在 registry 且不在收尾，不满足就抛并发关闭错误，不返回假的 reused: true
0 页复用isolated 模式补建一页后返回复用结果；CDP 模式报「CDP 浏览器已没有打开的标签页」的可诊断错误
空闲计时只在 idle / ready 装；launching / closing / closed 不装，启动落定后重新计时
会话键工具层用 exec.agent.id；无 agent 身份时退回全局 'global'。`session/disposed` 只给 Session，靠同源 session.id 精确回收

05编排：一次工具调用如何走完整条链

编排不在某个「总控类」里，而是三段各自的顺序：工具表负责解析会话与调能力函数；会话层把状态变化 广播成进程内事件；PanelHub 用一个 50 ms 防抖 + 串行队列把状态同步和投屏目标收敛到同一时刻。 工具路径与投屏路径互不阻塞。

编排里真正起作用的四个同步机制

机制位置解决什么
状态同步防抖 50 mspanel.js STATE_DEBOUNCE_MS一次导航连发多个页面事件，合并成一次 state 广播
同步串行化（共享 Promise）panel.js sync() / syncing并发同步共享同一次完成，避免投屏被并发启停
命令串行队列panel.js enqueue() / commandQueue同一条连接上的命令按到达顺序逐个处理，前一个失败不影响后续
投屏串行队列screencast.js enqueue() / queuestart / stop 不交错，结构性保证同时只有一个 CDP 投屏会话

06进程回收：三道兜底 + 一道关闭超时

浏览器进程挂在 DSH 服务上，对话结束、会话切走、子代理结束都不会自动回收。三道回收都在 lib/session.js 闭口；CDP 模式只断连，绝不结束用户浏览器进程。

07面板协议 v1 与「单一来源」纪律

host 与 client 只讲一个版本；路由、版本、命令、事件、错误码、投屏区间与默认值、panelTabId 组合规则全部只写在 lib/protocol.js。客户端不手写这些值，构建时注入。

路由与版本

  • GET /api/dsh-browser-e2e/state：只读状态快照（socket 连不上时兜底探测）
  • WS /api/dsh-browser-e2e/socket：协议 v1
  • 首帧 v 不等于 1 → 回 protocol-mismatch 并用关闭码 1002 断开；后续帧版本不符只回错误事件
  • 两条路由都过 fence.js：远端地址与 Host 头必须是 loopback，拒绝 sec-fetch-site: cross-site，非 loopback 在升级前就 403

命令（client → host，5 条）

  • attach{sessionId?}：绑定连接所属会话，回 hello{state}
  • select-tab{tabId}：选中并固定面板 tab
  • close-tab{tabId}：关页；最后一个页面回 last-tab
  • request-frame：立即截一帧 JPEG 推回（刷新按钮）
  • configure{config}：合并设置并重开投屏
  • 未知命令一律回 invalid-command，不静默丢弃

事件（host → client，5 条）

  • hello{state}：attach 的应答
  • state{state}：tab 列表 / 活动 tab / 运行模式 / 设置
  • frame{tabId, seq, width, height, data}：base64 JPEG，seq 单调递增，client 丢弃旧帧
  • action{trace:{tool, summary, at}}：工具动作提示
  • error{code, message}：code 取自 PANEL_ERROR_CODES

错误码（13 个，唯一来源）

  • 协议类：invalid-payload · protocol-mismatch · invalid-command · invalid-config
  • 标签页类：unknown-tab · last-tab · close-tab-failed · no-active-tab
  • 执行类：capture-failed · state-failed · config-sync-failed · command-failed · screencast-failed
  • host 侧代码不在调用点写 code 字面量；tests/invariants.mjs 断言表外没有字面量

panelTabId：跨会话同号 tab 不撞车

组合规则 key + '#' + tabId（如 example-session#t1）；拆分取最后一个 #， 因此会话 key 自身含 # 时仍能正确拆；# 在开头或末尾、非字符串一律返回 null， 由调用方转成 unknown-tab。唯一实现是 lib/protocol.js 的 panelTabId / parsePanelTabId，session.js 与 panel.js 都从那里取。

08边界、明确不做与已知结构性债务

明确不做（设计取舍，不是遗漏）

不建的抽象

  • 不建 abstract class / interface 关键字 / DI 容器 / 工厂：只有文件边界 + 纯函数 + 数据表
  • 不给 playwright-core 建 BrowserDriver 端口（只有一个适配器）
  • 不给 tab 建 class / 值对象；不按业务功能切 navigation.js / input.js
  • 不保留 browser.js 的 re-export 转发层

不拆的边界

  • isolated 与 cdp 不拆成两个模块（共享约九成逻辑，差异不是变化原因）
  • client/index.js 单文件不拆（以浏览器 bundle 形式分发，只 require react）

只读面板

  • 面板不启动浏览器、不操作页面；所有行为只能由 browser_e2e_* 发起
  • 唯一例外：close-tab 会真的关页
  • request-frame 只截一帧，不改变页面状态
  • configure 只改宿主进程内配置，不写回 profile

客户端注册面固定

  • 只注册 1 个 tab 类型 + 2 个 keyed 座位
  • 不注册 plugins.row.config / plugins.bundle.config / web-ui.plugin.item（当前宿主上会让 entry 激活失败，整个 GUI boot 失败）
  • 设置页由宿主按插件导出的 Config 自动渲染

已知结构性债务（规格记录于基线 1694b2c；本次按 HEAD d8a6264 逐条实测核对）

项现状未处置理由 / 建议
page.js 粒度过大1380 行、27 个导出：标签页注册表与生命周期、事件环、snapshot 的 DOM 启发式、七种交互、视口度量、展示格式化拆分面覆盖所有页面能力，回归风险高；建议拆 snapshot.js 与 observation.js
session.js 粒度过大682 行、16 个导出：会话注册表与状态机、launch/close 与回收、面板事件总线、面板读模型与工具能力面板读模型与事件总线属「面板视图」；建议拆 lib/view.js，但需先决定注册表暴露面。处置前不得再往 session.js 加职责
视口度量三份page.js 与 capture.js 各一份 viewportBounds，capture 另有内联兜底收敛会改依赖图（capture 现只依赖 protocol），留待拆 page.js 时一并处理
串行队列两份panel.js 与 screencast.js 各一份 enqueue/queue，逻辑相同抽出公共模块会增加一条依赖边并改依赖图，留待拆分评估

client 文案 / 样式孤儿键删除死组件后留下 17 个无引用 EN 文案键（45 键中）与 9 个无引用样式键（44 键中）；规格基线记 9 + 8整洁度问题，不影响行为；清理需与 client-bundle 文案断言一起核对
默认值散落tools.js 描述与 page.js 写死「默认 100」「默认 10000」，尚无单一来源；evaluate 的默认 / 下限 / 上限已收敛为 DEFAULT_EVALUATE_TIMEOUT_MS / MIN_EVALUATE_TIMEOUT_MS / MAX_EVALUATE_TIMEOUT_MS需新增常量并补规格的常量口径

已知限制（行为层面）

  • 面板是单 Hub 的全局视图：activeTabId 不按连接隔离。多个会话同时打开面板时，显示哪个 tab 由最后一次 attach / select-tab 决定；按连接隔离需要 per-connection 视图状态，超出当前实现范围。
  • 同一会话并发启动：只允许一次 launch，后到者等前一次落定后按复用返回；等待期间会话被 close，后到者收到「浏览器已关闭（启动与关闭并发）」。
  • 快照体积：4000 条上限，实测 4100 个简单 div 的页面模型可见文本约 189 KB；大页面建议直接用 selector 操作。
  • profile 里是 commit 快照：改完源码必须 commit + push 再在 profile 重新解析，否则跑的还是旧提交。
