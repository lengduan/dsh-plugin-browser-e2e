# 需求输入：动画动态守护（freezeAnimations 拦不住导航后新造动画）

> 本文是投给「需求流水线」小队的**需求内容**，不是施工步骤。具体拆解、实现顺序、验证方式由流水线的
> 规划 → 开发 → 测试 → 复核 各阶段动态处理；复核不通过打回规划重走。

## 1. 背景与结论依据

功能规格 0040 已记载并实测确认：`freezeAnimations` 只作用于 `domcontentloaded` 那一刻**已存在**的动画。
之后新造的动画不受约束，仍 `playState === 'running'`。

2026-11-21 用真实系统 Edge 复测（`.scratch/probe-anim-gap.mjs`），把「拦截不到的路径」拆开：

| 场景 | 冻结后 running | 说明 |
|---|---|---|
| 冻结后新元素挂**既有 class** 的 CSS 动画 | 0 | 注入的 `animation:none!important` 覆盖新元素，已能拦住 |
| 冻结后页面**自插 `!important` 样式** | 1 | 后插优先级更高，跑掉 |
| 冻结后 **WAAPI** `element.animate()` | 2 | 注入样式对内存里的 Animation 对象无效，跑掉 |
| 补一次 `pause()` 全量 sweep | → 0 | 上述两条都能收掉 |
| `patch Element.prototype.animate` + 250ms 周期 sweep | → 0 | 后建 WAAPI 也被原地拦住 |
| 1512 节点下 `getAnimations()` 单次耗时 | **0.039 ms** | 周期 sweep 的成本可忽略 |

另据上一轮会话（session-bf4a3e8c）的 10 组实测：`setCPUThrottlingRate`、`playbackRate`、
`Page.setWebLifecycleState('frozen')`、`reducedMotion` 均**不省 CPU 或无效**；只有「真正停掉动画」才省。
因此本需求的方向是**动态检测并停止**，不是节流。

## 2. 目标

页面在开启冻结后，**任何时刻新出现的动画都不应持续消耗 CPU**，包括：后建元素挂 CSS 动画、
页面自插更高优先级样式、`element.animate()` 新建 WAAPI 动画。开关关闭时必须真正撤守，
不能只改标志位。

## 3. 验收口径（可执行、可量化）

1. `node tests/freeze.mjs` exit 0、无 FAIL，且新增覆盖：后插 `!important`、后建 WAAPI 在守护开启后必须 `running === 0`。
2. **阴性对照必须存在**：同一段造动画脚本在未开守护的页面必须留下 `running >= 1`，证明断言非恒真。
3. 关闭开关后回到原行为：新造动画重新 `running >= 1`，即守护确实被撤掉。
4. 换文档（navigate / reload / recipe 内 goto / CDP 接管）后守护自动重装。
5. 真机对照：DSH GUI 上「不冻结 / 仅冻结 / 冻结+守护」三组的主线程占用（CDP `Performance.getMetrics` 的 TaskDuration）
   与 running 动画数如实记录；守护组的占用不得高于「仅冻结」组。
6. 浏览器控制回归：`tests/reclaim.mjs`、`tests/invariants.mjs`、`tests/tools.mjs` 不回归。

## 4. 架构约束（硬性）

按 `specs/项目规格/0001-architecture-invariants.md`：

- 三层归属：工具定义只在 `lib/tools.js`；编排在 `lib/index.js` / `lib/panel.js`；实现在能力模块；
  跨调用不变量只在 `lib/invariants.js`，入参校验留在能力函数。
- **按变化原因拆分**：动画抑制是有独立变化原因的能力，不应继续堆进已 2916 行、且已在「已知结构性债务」
  里记为粒度过大的 `lib/page.js`。
- 新模块必须登记进模块表（含「明确不含」）与依赖方向图，依赖单向。
- `throw` 分类按 0001 的 P3 口径：跨调用不变量进 `invariants.js`，入参校验与运行时结果留能力函数。
- 规格先行：语义变化要先改 `specs/功能规格/0040-animation-freeze.md`，其「已知局限」段落需改写。

## 5. 顺带登记的架构偏差（本需求范围内一并处置，由规划定归属）

上一轮核查已确认以下几处与 0001 不符，请规划在方案中明确处置方式（修 / 登记 / 明确延后并记录理由）：

- `lib/browser-profile.js`（185 行）被 `lib/pool.js` 依赖，但**未登记模块表、不在依赖方向图**。
- `specs/功能规格/` 下 `0041-browser-pool.md` 与 `0041-lockscreen-probe.md` **编号撞号**，0001 里「功能规格 0041」的引用有歧义。
- `lib/pool.js` 的锁屏闸门 `assertSafeToLaunch` 动态 `import('../native/lockscreen/probe.js')`，
  既未登记依赖边，也与「池只管进程申请与释放」的职责声明不同源。
- `lib/pool.js` 槽状态非法转移的 `throw` 属跨调用不变量，按 P3 应归 `invariants.js`。

## 6. 边界与不做

- 不引入 CSS / CDP 层面的节流（已实测无效或不省 CPU）。
- 不改 `playwright` 启动参数。
- 不动与动画无关的页面能力、事件环、ref 表、快照基线。
- 需要复现或测试动画本身时，用户仍应传 `freezeAnimations=false`——守护必须能被真正关掉。
- 跨源 iframe 无法注入；若纳入守护，需在规格里写明只覆盖同源 / 主文档，不得声称覆盖全部。
