# 功能规格

一个功能点一份文件。写清「输入 → 行为 → 可验收的结果」，实现前先写，实现后同步更新。

写代码前先读本目录里与需求对应的文件；没有对应文件时，先补这一份再动手。

## 模板

新建 `NNNN-<slug>.md`（`NNNN` 从 `0001` 递增，`slug` 用小写英文短横线），内容按下面五节：

```markdown
# <功能点名称>

状态: 草稿 | 已确认 | 已实现
关联: specs/项目规格/0001-xxx.md（没有就写「无」）
代码: lib/xxx.js / client/index.js / tests/xxx.mjs

## 需求

要解决的问题，以及使用者能看到的收益。一两句。

## 行为

- 输入：参数名、类型、区间、缺省值、互斥关系。
- 输出：返回形状、写入位置、失败时的错误信息。
- 状态变化：会话 / 标签页 / 面板 / 浏览器进程分别变成什么样。

## 边界

- 非法输入、并发、超时、宿主缺服务时的表现。
- 明确不处理的场景。

## 验收

每条都要能被一次具体检查判定：跑哪个 `node tests/xxx.mjs`、看到什么输出、页面 / 面板 / 进程状态如何。
写「它工作正常」不算验收。
```

## 约定

- 一份文件只写一个功能点；相邻功能点在文内互相链接，不合并成一份。
- 行为变了就改对应文件；新增文件时同步在上面模板的「关联」里引用项目规格的相关条目。
- 验收标准写可执行的检查，不写主观描述。
