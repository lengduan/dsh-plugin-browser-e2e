状态: 已实现
关联: specs/项目规格/0001-architecture-invariants.md（模块表、进程内对象契约「session 对象」、会话状态机、进程回收三道兜底）；specs/项目规格/0002-panel-protocol-v1.md（契约：`state` 的 `mode` / `endpoint` 由会话推导）
代码: lib/session.js / lib/page.js / lib/tools.js / lib/index.js / lib/carrier.js / lib/auth-state.js / lib/capture.js / tests/invariants.mjs / tests/multitab.mjs / tests/cdp.mjs / tests/reclaim.mjs / tests/panel.mjs / tests/carrier.mjs / tests/auth-state.mjs

## 需求

同一会话要能按需拉起本机系统 Edge，或接管已开远程调试端口的浏览器；重复调用 `browser_e2e_start` 复用同一实例，参数不一致时明确拒绝而不是悄悄换浏览器。收益：启动语义（缺省、失败清理、并发、复用）可预期，调用方不必自己判断「该不该再 start」。

## 行为

- 入口：`lib/tools.js` 的 `buildToolTable` 里 `browser_e2e_start`，参数全部可选：`headless`（boolean）、`proxy`（string）、`viewportWidth` / `viewportHeight`（number）、`mode`（枚举 `isolated` / `cdp`）、`cdpEndpoint`（string）、`carrier`（枚举 `edge` / `chrome` / `auto`）、`storageState`（string，宿主绝对 .json）、`storageDomains`（string[]）；根 schema 由 `params` 生成，`additionalProperties: false`，没有必填字段。`run` 调 `lib/session.js` 的 `launch(sessionKey(exec), args, exec?.agent?.id, launchDefaults())`，把插件配置默认值作为第四个参数传，不合并进 `args`。
- 缺省来源：`mode` 取 `options.mode ?? defaults.mode`，只认 `cdp`，其余落 `isolated`；`defaults.mode` 由 `lib/index.js` 的 `launchDefaultsOf` 只放行 `isolated` / `cdp`；`headless` 默认 `true`；`proxy` 取 `options.proxy ?? process.env.DSH_BROWSER_PROXY ?? ''`；视口取 `options.viewportWidth ?? DEFAULT_VIEWPORT.width` / `options.viewportHeight ?? DEFAULT_VIEWPORT.height`（`lib/page.js` 的 `DEFAULT_VIEWPORT`）；`carrier` 取 `options.carrier ?? defaults.carrier`，再缺省 `edge`（`lib/carrier.js` 的 `DEFAULT_CARRIER`），`defaults.carrier` 由 `launchDefaultsOf` 只放行三个合法值；`cdpEndpoint` 经 `normalizeCdpEndpoint(options.cdpEndpoint ?? defaults.cdpEndpoint)` 归一，都缺时取 `lib/defaults.js` 的 `DEFAULT_CDP_ENDPOINT`。插件配置侧的缺省来源见 `0006-plugin-config-and-live-apply.md`。
- 隔离启动：`launch` 先按 `carrierOf(options.carrier ?? defaults.carrier)` 归一、再用 `lib/carrier.js` 的 `detectCarrier` 解析：`edge` 不探测文件，`chrome` 按「`DSH_BROWSER_CHROME_PATH` → PATH 上的 chrome → 平台惯例安装位置」找可执行文件，`auto` 先找 Chrome、找不到回退 Edge（详见 `0034-multi-carrier.md`）。随后调 `chromiumImpl.launch`（缺省即 playwright-core 的 `chromium`）：`edge` 传 `channel: 'msedge'`、`chrome` 传探测到的 `executablePath`（不传 `channel`），都带 `headless` 与 `ignoreHTTPSErrors: true`，`proxy` 非空时加 `proxy: { server }`；随后创建**每会话一个显式 context**（`browser.newContext({ viewport, storageState? })`），再用 `context.newPage()` 建首屏，`addPage(session, page, 'created')` 生成首个标签页 `t1`（`session.nextTabSeq` 从 1 起），置 `session.mode` / `session.carrier` / `session.browser` / `session.context` / `session.viewport`（导入时另置 `session.storageState = { path, domains }`），广播 `opened` 面板事件，再由 `lib/capture.js` 的 `ensureArtifactsDir` 建产物目录。`storageState` 在启动前同步读取校验（见 `0021-auth-state-import.md`），非法时不拉起浏览器、不留半初始化会话。返回 `{ reused: false, mode, headless, channel?, carrier, version, viewport, tabs: 1, artifactsDir, storageState?, summary }`（`channel` 只在 `edge` 时出现，`storageState` 只在传了导入参数时出现），摘要为 `启动浏览器 ${carrierLabel} ${version}（headless=${headless}，视口 ${session.viewport.width}x${session.viewport.height}）`——`edge` 且未导入时即 `启动浏览器 系统 Edge …`，与实现前逐字相同；导入时追加 `，已导入 N 个 cookie、M 个 origin（D 个域名）`。
- CDP 接管：`mode: 'cdp'` 时 `launch` 走接管分支（`connectOverCDP` 建连、逐页 `addPage(..., 'adopted')` 登记、`context.on('page')` 增量接入），不新建页面、不设视口、不传 `headless` / `proxy`，也不参与载体选择（`carrier` 被忽略，`session.carrier` 固定记 `edge`，摘要与返回形状保持原样、不带 `carrier`）。接管的前置校验、页面 adopt 细节、增量接管与「close 只断连」等行为见 `0008-cdp-attach.md`；本文件只约定该分支在 `launch` 内的返回形状 `{ reused: false, mode: 'cdp', endpoint, version, tabs, summary }` 与摘要 `接管 CDP 浏览器 ${endpoint}（${session.pages.size} 个标签页，系统 Edge ${version}）`。
- 工具渲染：`browser_e2e_start` 的 `run` 按返回分支拼文本——复用输出摘要与 `当前地址：${info.url || '空白页'}`；CDP 追加 `接管端点：${info.endpoint}` 与 `CDP 模式不会关闭你的浏览器，browser_e2e_close 只断开连接。`；隔离追加 `产物目录：${info.artifactsDir}`。
- 复用分支：`session.browser` 已存在时先 `assertReuseCompatible`——只对显式传入的 `options.mode` / `options.cdpEndpoint` / `options.carrier` / `options.storageState` 做一致性校验（`assertModeNotHotSwitched` / `assertEndpointNotHotSwitched` / `assertCarrierNotHotSwitched`），配置默认值不参与；`carrier` 的一致性校验只在隔离会话上做，`auto` 先解析成具体载体再比较；`storageState` 只在「同一隔离会话、同一路径、同一 storageDomains 归档结果」时允许复用（并发 start 带同一份登录态），否则按热导入拒绝。复用分支同样建立 `launchingPromise` / `launchTask` 落定信号，收尾时清掉。`reuseInfo` 返回 `{ reused: true, mode, carrier, version, url, tabs, summary }`，其中 `carrier` 是会话实际载体（CDP 时为 `edge`）、`version` 取 `browser.version()`、`url` 取当前 active 页地址（无页为空串），摘要为 `浏览器已启动（${session.mode === 'cdp' ? 'CDP 接管' : '隔离'}模式，${carrierLabel} ${session.browser.version()}，${session.pages.size} 个标签页）`。
- 复用且 0 页：隔离模式用 `createPage` 补建一页、`addPage` 登记并把 `activeTabId` 切到新页后返回复用结果；CDP 模式直接抛 `CDP 浏览器已没有打开的标签页，请在浏览器里新建标签页，或先 browser_e2e_close 再重新 browser_e2e_start`，会话停在 `ready`。
- 并发启动：同一 key 的 `launch` 发现 `session.launchTask` 存在时只等它落定，不另起浏览器；落定后依次过 `assertNotClosedDuringLaunch`、`assertLaunchSettled`、`assertReuseCompatible`，再按复用返回。
- 并发关闭：`lib/session.js` 的 `close` 先同步摘除注册表与会话状态（`idle` 直接进 `closed`，`launching -> closing` 或 `ready -> closing`），有 `launchingPromise` 时等它落定；启动路径的 `ensureAlive`（内部调 `assertNotClosedDuringLaunch`）在 `chromiumImpl.launch` / `connectOverCDP` / `browser.newContext` / `context.newPage()` 之后各查一次，被 close 就立刻停下。

## 边界

- 非法 `mode` 在登记会话之前直接报 `mode 只支持 isolated / cdp，收到 ${JSON.stringify(options.mode)}`，不静默降级成 `isolated`，也不留下会话条目；非法 `carrier` 同口径报 `carrier 只支持 edge / chrome / auto，收到 ${JSON.stringify(options.carrier)}`。
- 端点校验在 `normalizeCdpEndpoint`：不是 URL 报 `cdpEndpoint 不是合法 URL：${text}`；协议不是 http 报 `cdpEndpoint 只支持 http，收到 ${url.protocol}`；主机不是 loopback 报 `cdpEndpoint 只允许 loopback 主机（localhost / 127.0.0.1 / ::1），收到 ${url.hostname}`。
- 启动中被 close：`launch` 的 `finally` 看到 `session.state === 'closing'` 时先收掉可能已建立的浏览器——按本次局部 `mode` 决定用 `closeBrowser`（隔离模式；超时后只如实记录「进程可能残留」、不强杀，见 `0001`「关闭兜底」）还是 `browser.close()`（CDP 模式，只断连），再把 `closing` 落成 `closed`，不留半初始化会话与孤儿进程。
- 启动失败清理：`finally` 里 `launched` 仍为 false 且会话仍是 `launching` 时，清 `browser` / `context` / `pages` / `activeTabId`，按目标模式收掉浏览器；只有广播过 `opened` 的会话才补广播 `closed`；状态从 `launching` 走 `launchFailed` 回 `idle`；清理期间若已被 close，则按 `closeSettled` 收成 `closed`，不被启动结果覆写。
- 成功判据是「launcher 走完、浏览器在、至少一页」：`launched` 只在 `addPage` 之后置真，因此 `newPage` 抛错、CDP 没有 context / 已打开标签页等情况都算失败，不会停在 `ready + 0 页`。
- `headless` / `proxy` / `viewportWidth` / `viewportHeight` / `carrier` 只对隔离模式生效；`mode: 'cdp'` 下即使传视口或 `carrier` 也不作用于被接管的浏览器（`carrier` 被忽略，工具文本追加一行说明）。
- 热切换拒绝只由显式参数触发：已启动会话传了与当前不一致的 `mode` / `cdpEndpoint` / `carrier` 就由 `assertModeNotHotSwitched` / `assertEndpointNotHotSwitched` / `assertCarrierNotHotSwitched` 报错（文案见项目规格「不变量清单」），未传则复用原实例；`carrier` 只对隔离会话校验。
- 登录态只在启动时导入：已启动后再传 `storageState` 报 `浏览器已启动（isolated / CDP 接管）；storageState 只在启动时生效，如需更换登录态请先 browser_e2e_close 再 browser_e2e_start`，不重建 context；并发 start 带同一份 `storageState` 与 `storageDomains` 时按复用返回。`mode: 'cdp'` 与 `storageState` 同时给时在 `connectOverCDP` 之前报 `CDP 模式不导入登录态：接管的是用户自己的浏览器，其 cookie 由用户维护；请在 isolated 模式使用 storageState`。导入细节见 `0021-auth-state-import.md`。
- 空闲计时：`lib/session.js` 的 `touchSession` 在 `launching` / `closing` / `closed` 或 `IDLE_CLOSE_MS` 为 0 时不装计时器；`launch` 开头清旧计时器，`finally` 落定后重新计时，因此启动耗时超过 `DSH_BROWSER_IDLE_MS` 不会被中途回收（回收口径见项目规格「进程回收三道兜底」）。
- 复用分支补建页失败：先落定信号再 `close(key)` 收掉浏览器、摘除会话，然后把原始错误抛出，不留 `ready + 0 页`；复用成功返回前再用 `assertReuseAlive` 复查会话仍在注册表里，若与 close 并发则报 `浏览器已关闭（复用与关闭并发），请重新调用 browser_e2e_start`，不返回假的 `reused: true`。
- 隔离模式的载体可显式选择：`carrier` 只接受 `edge` / `chrome` / `auto`（`0034-multi-carrier.md`），默认仍是系统 Edge（`channel: 'msedge'`，不触发 360 进程防护弹窗）。工具参数不接受可执行路径：Chrome 路径只由 `DSH_BROWSER_CHROME_PATH` 与平台惯例安装位置决定。`mode` 只有 `isolated` / `cdp` 两个取值，其他值按上一条报错。
