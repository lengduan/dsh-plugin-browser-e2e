# 项目规格

项目级的稳定约束：这个插件做什么、不做什么，以及跨功能点必须一致的契约。

写代码前先读本目录；实现与这里冲突时，以这里为准。

## 放什么

- 范围与非目标：支持哪些宿主、模式、浏览器，明确不做什么。
- 架构约束：宿主半区、客户端、面板、协议之间的职责边界（例如「面板只是视图，不发起操作」）。
- 跨功能的契约：工具命名前缀、`tab_id` 语义、`state` 形状、配置字段与缺省值、进程回收口径。
- 里程碑与已知限制。

## 不放什么

- 单个工具或单个功能的详细行为与验收标准：写在 `../功能规格/`。
- 使用说明、命令清单、安装步骤：属于 `README.md`，不在这里复制一份。
- 一次性调研结论与讨论过程：留在会话或 `.scratch/` 里。

## 约定

- 文件名 `NNNN-<slug>.md`，`NNNN` 从 `0001` 递增，`slug` 用小写英文短横线。
- 一份文件一个主题；契约变更只改权威的那一份，同名含义不要在多份文件里各写一遍。
- 目录目前为空时，按需求直接新建，不必等集齐。
- 引用实现位置一律写「文件 + 符号名」（函数 / 常量 / 类 / 导出名），不写行号：行号随重构漂移，
  且规格更新往往滞后于代码。唯一例外是明确标注基线的历史存档表（例如 `0001` 的 throw 分类表与
  调用图表），必须写明「基线，不按当前文件校对」。
- 契约与数字以本目录为准。`docs/architecture.html` 是架构速览（含手绘依赖图与债务实测），
  与 specs 不一致时以 specs 为准；架构图里的数字需要在 specs 更新后同步，不得反向覆盖 specs。
